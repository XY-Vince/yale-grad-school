# 公开人物调查技能

对具名人物做一次证据锚定的公开调查，产出人能直接使用的档案：这个人目前可对应到谁、
有哪些公开记录、哪些人只是同名候选、还不知道什么、下一轮该查什么。

优先找全与用户目的相关、公开且适当的资料。围绕身份、职业、教育、作品与研究等适用维度
持续查找，保留同名候选和有用线索；关键维度漏查同样是调查缺口。明确区分已确认、待核实、
已查无结果、未查和受阻，不把推断写成事实，不把同名异人的记录挂到目标身上，不宣称穷尽
开放网络。

## 何时使用 / 何时不使用

使用：用户点名人物，要求调查、核实、补全或整理与任务相关的公开职业、学术或其他适当
资料；是否公众人物不是唯一的判断条件。按用户授权、必要性与来源政策控制调查范围。

不使用并直接说明：

- 用户要求聚合私人 PII（住址、电话、家属、行踪、健康记录）——来源政策明确排除，见
  `references/source-policy.md`，不要用"合法公开"绕开它；
- 禁止绕过登录、付费或 CAPTCHA 访问限制；目标难以区分时仍按低足迹情况调查，保留线索、
  已查范围和缺口，不造假填补。

## 默认流程（六步）

### 1. 理解目标与线索

从用户输入提取：目标姓名（及别名/中文/拼音变体）、机构、领域、大致时间、已知事实。
把线索当**消歧约束**，不当既定事实——路线是"承认事实存在，再判断归属"，不是"假设事实
为真再去找佐证"。用户给的种子链接优先处理并留存。

### 2. Agent 搜索与精读

工具自主选择（web 搜索、直接访问已知来源类型、机构 API）。要点：

- 多轮而非一次：每轮读完后，区分"还没查的类别"（机构页、CV、会议程序册、ORCID、
  Scholar、监管/官方登记）和"已查但读浅的来源"，下一轮攻前者。
- **失败的查询也要留痕**（写成 query_logs）——这是接手的人唯一能省下的重复劳动。
- 每页抓取即落盘原文（raw HTML/PDF/JSON），不要只存摘要或自己转写的文本。
- 数据库结果分别记录总数、请求页、实际返回及核查数量；未保存的后续页或个人详情不得
  宣称已查完。失败、登录墙、搜索摘要、零结果和“尚未查询”分别标记。
- 搜索摘要只作为待查线索；403/404 不证明具体人物记录存在或不存在。回到可访问原文，
  不臆造公开姓名的汉字写法。

### 3. 原文留存

每条候选证据登记 URL、抓取时间、HTTP 状态、用途、原始字节和 SHA-256。相同字节可
复用文件，但每次查询及结果关系仍须保留；不同结果中支持判断的内容不能按查询族丢弃。
将目标证据、机构背景、替代候选、检索噪声和 authwall 区分记录。

保存 HTTP 响应正文，记录实际请求 URL、最终 URL、状态、时间与抓取方式。解析文本和摘要
另存为派生内容；不得改写 HTML、补造作者、向 API JSON 添加摘要后称其为原始响应。
发现可疑捕获时保留旧文件及撤回记录，以新 source_id 留存重抓结果。将旧来源标记为
`evidence_status: "withdrawn"`；无法核实的来源标记为 `"unverified"`，两者不得支持 verified。
verified及正面佐证来源必须有实际HTTP 200响应，且不得标为authwall、检索噪声或抓取失败。
HTTP 200本身不证明正文可用；登录页不能当人物页。
正面证据必须显式标注 `evidence_status: "usable"` 或 `"verified"`；新抓取内容先由人或
agent 阅读后再标注，`PENDING_REVIEW` 只能作背景。旧案卷缺少该字段时，先核对并更新；
如仅为回看历史需临时运行审计，可加 `--allow-legacy-missing-evidence-status`，警告仍须复核。
该选项也会把旧未决线索的正面来源字段作为背景提示；它不将线索确认为已获佐证，
也不忽略缺失引用、证据不符或其他审计错误。

### 4. 候选消歧

同名不等于同一人。为不同身份或尚不能合并的记录组分配候选编号；有足够身份依据时锁定
目标，否则保留未决状态及候选。仅在本人双语自述、同一官方个人页面或其他可复核身份桥
明确支持时关联拼音、汉字和跨平台身份；同音、同机构或同页合著不足以单独证明。

**禁止**：凭同名合并；凭"同机构/同领域"合并；只因为找不到区分证据就认定同一人。
同名候选的断言在账本里也带候选标识：`subject: "Alice Example (CAND-04, Example University)"`，
`subject_raw` 保留来源原名。检索噪声页和 authwall 重定向（如 LinkedIn HTTP 999）
不是履历证据。

### 5. 分层：事实 / 线索 / 未知

四种强度，写每条断言前逐档判断：

| 档 | 名称 | 判定 | 写法 |
|---|---|---|---|
| S1 | 已确认发生 | 原文明确陈述已发生 | "机构名册列出……" / "本人自述已经……" |
| S2 | 公开意向 | "将做/期待"类表达 | "公开表达期待……"，不写"参与了" |
| S3 | 研究环境关联 | 出现在致谢/引用/工作场景，参与度不明 | "致谢……资源关联"，不写"主持/受聘" |
| S4 | 传闻线索 | 间接、未闭合、历史描述 | "待核实线索"，只作继续搜索的入口 |

每个 S1/S2/S3 断言落到证据（claim → verbatim 原文片段 → 本地文件）；S4 进线索账本。
可用 S4-x 标注受阻或不可读的检索残片：搜索摘要只供追查；403、登录墙或 CAPTCHA 只
证明本次访问受阻，不能据此确认具体人物记录存在或支持属性。
撤销的断言编号不回收。政策排除字段（住址、电话、家属等）不得为凑完整性去查。

线索字段明确区分：`corroborating_source_ids`只列可用的正面佐证；
`context_source_ids`记录发现/失败过程；`withdrawn_source_ids`仅追溯撤回材料。
若标为`CORROBORATED`，逐来源提供`supporting_evidence`（`source_id`、`subject_raw`、
`object`、`verbatim_excerpt`、`locator`）；机械回放与主体/词句匹配仍不能替代语义复核。
没有证据的具体履历不得靠无关文件挂接；未确认的检索提示保持`UNRESOLVED`。

### 6. 输出档案

结构照 worked example（目标人物 / 同名候选 / 缺口与下一步）。硬性要求：

- 事实性分句就近挂 claim_id；时间线与汇总可挂条目级聚合引用。
- 结尾必有缺口清单（用户现在还不知道什么）与下一轮搜索方向。
- 区分"本人自述"与"机构独立记录"——证明力不同，分别呈现。
- 学位候选名单不证明获得学位；股东记录不证明雇佣关系；预计毕业年份不证明入学年或学制。
- 身份、时间、来源强度和搜索范围在报告、候选矩阵及账本中保持一致。
- 核对名单所在分节标题（包括`Candidates for Degrees`），不能仅凭“姓名，BA”等短行断言授予学位。
- 按`dossier.primary_candidate_id`统计目标断言；目标为零时标记`INSUFFICIENT_EVIDENCE`。
  同名候选事实可以保留，但仍需完整引用检查；不能用其数量替代目标证据。
- 为所有 evidence_index.md 引用建立对应 VCLM / LEAD / OQ 锚点，逐一检查可点击目标。
- 案卷内Markdown链接用相对路径，不写本机绝对路径。

机械自检（防呆，不是验收指标）：

```bash
PYTHONPATH=<skill 根> python3 scripts/verify_investigation_bundle.py --bundle-dir <案卷目录>
```

复核只阻断四类实质问题：伪造来源、错误主体归属、未证推断当事实、违反来源政策。
其余（命名、指标、测试计数、治理）进 backlog，不得用于扣留交付。
PASS 只表示机械一致性；哈希不能证明响应真实，token 重合不能证明语义蕴含。审计器会提示
未标引正文和词面异常，需逐条人工判别并补引用或删除越界断言；提示本身不是事实分类器。

可用 `scripts/bundle_files.py` 留存响应和更新指定文件的 manifest；它不判断人物身份、
关系或证据是否支持结论。保留自然语言报告，词面匹配提示不作为语义正确的证明。
新建案卷中，能单义对应断言的 `dossier.json` statement 应填写一致的 `candidate_id`、
`predicate`、`object`；多条断言字段不同时，拆分陈述或保留待核查，不自行选择。
审计器仅在字段存在时校验，缺失字段本身不会阻断；旧案卷补填前仍须复核。
`align-statements --bundle-dir <案卷目录>` 可预览从已引用断言复制结构化字段；
`--apply` 写入后须更新 `dossier.json` 的 manifest。复制字段不能验证叙述，仍须阅读原文。
交付前运行 `scripts/lint_wording.py <案卷>/recall_report.md <案卷>/source_inventory.jsonl`。

## Worked example

私人调查案卷及其编辑记录保存在单独的私有归档中，不随公开代码仓库分发。
有权访问该归档时，可参照其中的 worked example；否则按本文件所述的证据强度、
候选归属与引文要求组织报告。
部分历史真实人物基准和回放材料同样保存在私有归档；没有这些材料时，
公开检出中的相关测试会明确跳过，不能把跳过视为通过。

## 附录：legacy 自动管线与内部评测（非日常路径）

日常调查走上面的 agent 流程。以下内容只服务于回归与历史追溯，**不是必经步骤**：

- `core.run_profile`（确定性正则管线）：只支持单人候选，召回与强度判断天花板低；
  保留作回归基线，不要用它产出用户档案。
- `scripts/run_recall_profile.py` 仅作历史实验：新运行须使用空输出目录，不能用 `--resume`
  覆盖旧案卷。`--discovery-file` 可在新目录显式读取旧发现列表；其他检索仍可能联网。
- `references/threat-model.md`（SSRF/注入防护）、`references/source-policy.md`
  （来源边界与排除类别）：调查前读一遍，约束抓取行为。
- `.agents/rules/05-investigation-execution-contract.md`（调查执行契约）：硬约束与
  停止规则，与本技能默认流程冲突时以本文档为准。
- `benchmarks/`（V1–V10 盲测协议与历史报告）：发布级证据工作，从未产出聚合指标；
  日常交付不引用这些数字。
